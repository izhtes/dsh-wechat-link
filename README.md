# 链接微信（dsh-wechat-link）

> 维护是不定期的：**不保证运行效果**
> 本项目最早来自[thawline/dsh-wechat-bridge](https://github.com/thawline/dsh-wechat-bridge)（MIT）

**链接微信：让DSH和微信双向互通** 你在微信里发的话转进DSH，它说完之后再发回微信

**注意**——做不到后台发消息：每次发送都会操作微信窗口，会抢焦点、移动鼠标、模拟键盘，发送那几秒请不要动鼠标键盘，否则可能点错窗口或把字贴到别处

- 收消息：读微信4.x的本地SQLite数据库（只读，要求微信处于登录状态）
- 发消息：Windows UI Automation+剪贴板，驱动微信窗口打字、粘贴图片

它用的是**你自己的微信号**，不是bot，在朋友眼里，就像是你本人在说话

## 功能

收发消息，以及：让它说话别那么像机器，出问题能及时发现

- 没人找它的时候会自己说一句，但不会一直说，最近有没有人聊天、是不是正在说话，都会看一眼，不想说就不说
- 可以指定几个群，群里不点名也能接话，配了间隔和每小时上限，免得刷屏
- 回复不会一两秒就发出去，真发之前会等一会儿，默认8到25秒，嫌慢可以调小或者关掉
- 太长的回复会按句子拆成几条发，每条最多60字，条与条之间隔1到2秒
- 加了一个`wechat_send`，能主动往指定的聊天发一句，不用等对方先开口
- 微信掉线、DSH连不上这类事，桥接会在日志里记一条，不会悄悄断掉；DSH没回来时来的消息先存着，一小时内能补进去
- 表情包、发送确认、发图速度、断句长度这些细节都调过，发一条就是一条

具体改动见[CHANGELOG.md](CHANGELOG.md)

## 运行逻辑

| 方向 | 链路 |
| --- | --- |
| 收消息 | 微信本地库 → Python桥接 → `POST /dsh-wechat-bridge/receive` → DSH会话 |
| 发消息 | DSH会话 → `GET /dsh-wechat-bridge/outbox` → Python桥接 → UIA → 微信 |

宿主管会话绑定、权限、队列；Python桥接管读库、发送、日记；中间走本机HTTP

## 安装方法

```
dsh plugin --profile desktop add github:izhtes/dsh-wechat-link
```

或设置→插件→安装，填`github:izhtes/dsh-wechat-link`

装完**重启一次DSH**，打开**设置→链接微信**

**重启DSH之后桥接不会自己起来**：每次重启都要进「设置→链接微信」点一次「启动」（或者调`POST /dsh-wechat-bridge/bridge/start`），日志里滚出「桥接已就绪」才算通

## 启动

1. **环境**：需要Python和`wechatauto-replica`那一套（`pip install wechatauto-replica numpy`），版本不限；把`python.exe`路径填进设置里的「解释器」（留空自动找）
2. **启动**：点「启动」之后，下面会滚日志，看到「桥接已就绪」说明启动成功
3. **选会话**：选择DSH会话当作「默认会话」，打开「总开关」，先留着「试运行」看它记的「该发什么」对不对，对了再把试运行关掉

之后在微信里跟**文件传输助手**说话，就等于跟它说话；别人的私聊会转进来，群里的消息按群规则进——但**外人只能聊天，动不了电脑**（见下面「权限」），不想让某个人进来，填「入站白名单」（留空=谁都能进）

## Python环境

插件没有自带Python，也不建虚拟环境，你得自己有一个装好`wechatauto-replica`的Python：

```
pip install wechatauto-replica numpy
```

`wechatauto-replica` 的源码在 https://github.com/fanyuantaier/wechatauto-replica

Python版本不限，微信没有硬限制，但上游wechatauto按微信版本硬编码控件地址，微信升级后可能失效；装不上是上游包的问题，跟插件无关，装好后把`python.exe`路径填进设置里的「解释器」；留空的话，插件会扫本机装过的Python，挑第一个能`import wechatauto, numpy`的用

装的时候卡住（下不动、报错、缺包），把报错整段贴给DSH，让它按报错处理——它能看到本机环境和日志，效率更高

## 权限

| 谁 | 能干什么 |
| --- | --- |
| **主人**（`主人`里填的wxid/昵称） | 什么都能做：聊天、读文件、跑命令、改设置 |
| **别人** | **只能聊天**，所有工具调用都会被拦截 |

实现方式：外部消息进来时，插件给那间会话的agent挂一道`tools.guard`，这一轮如果是外人叫醒的，任何工具调用都会被拒绝，只放行文字回复，这一轮结束闸就抬起来

所以外人就算在微信里说「帮我删掉D盘」，工具层直接拒绝，模型只能回一句「这个我做不了」

⚠️ 前提是宿主要提供`tools.guard`（本版本DSH有），没有的话日志会警告一句「这层宿主没有tools.guard」，那就只剩嘴上约束了

## 消息放行

默认**谁都能发进来**：任何能给这个微信号发消息的人，都能让本机模型跑一轮，会消耗token

想要添加限制，去设置里填**入站白名单**：填了之后只有名单里的wxid/昵称能发进来，日志里记一句就丢掉，**主人永远放行，不用写进来**，留空=恢复成谁都能进

两层的关系：

| 层 | 挡什么 | 怎么配 |
| --- | --- | --- |
| 入站白名单 | 谁的消息能触发一轮 | 留空=谁都能进；填了只放行名单 |
| 外人只能聊天 | 触发之后能不能动电脑 | 默认开；主人才放行工具 |

## 群聊

| 设置 | 作用 |
| --- | --- |
| **群上下文条数** | 被叫到时，往前读几条群聊天一起给模型看，默认6，填0=不带 |
| **群回复间隔秒** | 同一个群，两条回复之间至少隔几秒，默认30，填0=不限 |
| **群每小时上限** | 同一个群一小时最多接几次，默认6，填0=不限 |
| **群聊日记** | 群里**所有**消息（不点名的也记）按天写成markdown |
| **不回谁（屏蔽）** | 一条一个标签，命中的会话/人不回复也不记日记（默认：微信运动、微信团队、微信支付、服务通知、订阅号消息、折叠的群聊） |

群里默认**只有主人说话才进**，想在群里被点名接话，把`bridge/wechat_bridge.py`的`DEFAULT_ALIASES`改成你的名字（逗号分隔，例如`"小助手,助手"`），改完重启桥接

日记存在`~/.dsh/wechat-diary/<YYYY-MM-DD>/<群名>.md`，一天一个文件，不喜欢可以关掉该功能

## 表情包

配合`dsh-meme`插件使用，AI在回复里写`[表情: 描述]`，插件会去`dsh-meme`的表情库里按caption/关键词找那张图，**当图片消息发到微信**，那串描述本身不会出现在正文里，找不到对应图片时保持原样（发出去的就是文字），不会丢内容

| 项 | 默认 | 说明 |

| 接口令牌 | 空 | Python侧请求要带的口令，留空不校验 |
| 解释器 | 空 | 一个装好`wechatauto-replica`的`python.exe`；留空=自动扫本机Python |
| 主人 | 空 | wxid或昵称，逗号分隔 |
| 外人只能聊天 | 开 | 见上面「权限」 |
| 群上下文条数 | 6 | |
| 群回复间隔秒 | 30 | |
| 群每小时上限 | 6 | |
| 群聊日记 | 开 | |
| 日记目录 | 空 | 留空=`~/.dsh/wechat-diary` |
| 屏蔽 | 见上 | 一行一个 |

额外功能（存在同一个配置文件里，设置页有对应的格子）：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 活跃群 | 空 | 群名或`xxx@chatroom`，逗号分隔，填了这些群「不点名也接话」；留空=只有点名/主人说话才进 |
| 主动对话 | 关 | 闲一阵自己开口，间隔、时段、最近有没有人在聊、是不是正在说话，都会看 |
| 主动间隔分钟 | 90 | 两次主动之间至少隔多久（最小5） |
| 主动时段起/止 | 8/23 | 只在这几个小时里主动；起=止视为全天 |
| 主动提示 | 空 | 自己开口时给模型的提示词，留空用内置的 |
| 主人显示名 | 空 | 只用在拿不到wxid的场合；填备注名（如「主人」） |
| 回复延迟下限秒/上限秒 | 8/25 | 真发之前随机等这么久（都填0=不等，秒回） |

配置在`~/.dsh/wechat-bridge-config.json`，改完点保存，**桥接30秒内自动生效，无需重启**

## 让DSH帮你

直接跟它说一句就行——插件挂了这几个工具：

| 工具 | 参数 | 干什么 |
| --- | --- | --- |
| `wechat_block` | `{who, action: add / remove / list}` | 加/删/看「不回谁」名单 |
| `wechat_bind` | `{chat, session, action}` | 把某个微信聊天接到某间会话；`session`可以只报标题（如「主要聊天记忆」），它自己去找那一间 |
| `wechat_send` | `{聊天, 文本}` | 主动往某个微信聊天发一句（显示名、wxid、`xxx@chatroom`都认） |

## HTTP接口

| 方法 | 路径 | 干什么 |
| --- | --- | --- |
| POST | `/dsh-wechat-bridge/receive` | 收：`{text, 图片?, 图片类型?, chat, chatId, chatType, sender, senderId}`→转进会话 |
| GET | `/dsh-wechat-bridge/outbox` | 发：取走待发队列 |
| POST | `/dsh-wechat-bridge/outbox/ack` | 发完回报 |
| GET | `/dsh-wechat-bridge/state` | 状态、配置、会话、日志 |
| POST | `/dsh-wechat-bridge/save` | 保存配置 |
| POST | `/dsh-wechat-bridge/test-send` | 发一条测试消息 |
| POST | `/dsh-wechat-bridge/vision-test` | 试看一张本地图片：`{图片, 类型?}` |
| POST | `/dsh-wechat-bridge/bridge/start`/`stop` | 起停桥接 |
| POST | `/dsh-wechat-bridge/send` | 主动发送：`{聊天, 文本, 图片?}` |
| POST | `/dsh-wechat-bridge/proactive-now` | 立即测试「自己开口」（自检用，无视闲多久） |
| POST | `/dsh-wechat-bridge/notify` | 桥接汇报（微信掉线、DSH连不上），只记日志、不开会话 |
| POST | `/dsh-wechat-bridge/test-inbound` | 假装收到一条消息，验路由 |
| GET | `/dsh-wechat-bridge/check-update` | 检查版本更新 |
| GET | `/dsh-wechat-bridge/bridge/status` | 桥接进程状态（比`/state`轻） |

## 局限性

- **图片和表情包会先“看”一眼**：收到图片/表情包时，桥接先把文件落盘，宿主用视觉模型写成一句中文描述再转进会话；没配视觉密钥时会标「没看清内容」，不会挡消息，语音、视频仍然跳过
- **发送一定会抢鼠标和焦点**：无hook，每次发送都会移动鼠标、占用键盘几秒，期间尽量别操作电脑；切换会话、发图或坐标兜底时会把微信窗口拉到前面，文字发送失败也会切前台重试
- **同一个微信号别同时开两个桥**（比如别的微信桥接），会抢窗口、发送会乱
- 微信个人号自动化不是官方接口，**有封号风险**，建议先用小号/测试号
- 微信升级可能让它失效：`wechatauto`靠一张按版本号硬编码的地址表找控件树，升级后发不出去先看设置页下面的日志
- 只在Windows上能用（UI Automation是Windows独有的）

## 自我验证

先跑随包带的两个自测（改过`lib/host.js`或`lib/client.js`也跑这个，不用开DSH，记得把`DSH_HOME`指到临时目录）：

```powershell
$env:DSH_HOME="$PWD\.testhome"; node _selftest.mjs         # 假 ctx 跑一遍宿主：保存 / 绑定 / 屏蔽 / 三个工具
$env:DSH_HOME="$PWD\.testhome"; node _selftest_client.mjs  # 假 React 把设置页渲染一遍：加标签、点绑定、轮询不冲掉
```

再往「文件传输助手」真发一条，日志里要出现`✅ 已发到微信`和`✅ 库里确认已发出`

文件传输助手是留给你自己的对话窗：自己发给自己的消息本来会被跳过（防自问自答），但文件传输助手放行
两道防回环：
1. 自己刚发出去的几条，按文本比对跳过（比对前先规整空格换行）
2. 往外发完的12秒内，文件传输助手里冒出来的消息一律不读
